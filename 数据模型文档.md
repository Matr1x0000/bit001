# 社区管理系统数据模型文档

## 1. 模型概述

本系统包含14个数据模型，主要分为以下几个模块：

- 社区基础信息（社区、社区工作者）
- 房产信息管理（小区、楼栋、单元、房号）
- 居民信息管理（家庭、居民）
- 通知管理（通知、通知阅读状态）
- 用户管理（用户扩展信息）

## 2. 模型详细设计

### 2.1 Community - 社区模型

| 字段名         | 类型           | 约束     | 描述     |
| -------------- | -------------- | -------- | -------- |
| id             | AutoField      | 主键     | 社区ID   |
| name           | CharField(50)  | 必填     | 社区名称 |
| office_address | CharField(100) | 可选     | 办公地址 |
| office_phone   | CharField(15)  | 可选     | 办公电话 |
| created_at     | DateTimeField  | 自动生成 | 创建时间 |
| updated_at     | DateTimeField  | 自动更新 | 更新时间 |

**关系**：

- 一对多：社区 → 社区工作者
- 一对多：社区 → 小区
- 一对多：社区 → 胡同

### 2.2 SocialWorker - 社区工作者模型

| 字段名       | 类型                  | 约束      | 描述                              |
| ------------ | --------------------- | --------- | --------------------------------- |
| id           | AutoField             | 主键      | 工作者ID                          |
| community    | ForeignKey(Community) | 可选      | 所属社区                          |
| name         | CharField(20)         | 必填      | 姓名                              |
| gender       | SmallIntegerField     | 默认1     | 性别（1:男, 2:女）                |
| phone        | CharField(15)         | 可选      | 联系电话                          |
| birth_date   | DateField             | 可选      | 出生年月                          |
| is_secretary | BooleanField          | 默认False | 是否为书记                        |
| is_baned     | BooleanField          | 默认True  | 是否在职（True:在职, False:离职） |
| created_at   | DateTimeField         | 自动生成  | 创建时间                          |
| updated_at   | DateTimeField         | 自动更新  | 更新时间                          |

**关系**：

- 多对一：社区工作者 → 社区

### 2.3 HousingEstate - 小区模型

| 字段名           | 类型                  | 约束     | 描述     |
| ---------------- | --------------------- | -------- | -------- |
| id               | AutoField             | 主键     | 小区ID   |
| name             | CharField(50)         | 必填     | 小区名称 |
| address          | CharField(100)        | 可选     | 小区地址 |
| community        | ForeignKey(Community) | 可选     | 所属社区 |
| property_company | CharField(50)         | 可选     | 物业公司 |
| property_phone   | CharField(15)         | 可选     | 物业电话 |
| created_at       | DateTimeField         | 自动生成 | 创建时间 |
| updated_at       | DateTimeField         | 自动更新 | 更新时间 |

**约束**：
- unique_together：(name, community) - 确保同一社区内小区名称唯一

**关系**：

- 多对一：小区 → 社区
- 一对多：小区 → 楼栋

| ------------ | ------------------------- | -------- | -------------------------- |

| single_house | ForeignKey(SingleHouse)   | 可选     | 平房房号（平房地址关联）   |
| created_at   | DateTimeField             | 自动生成 | 创建时间                   |
| updated_at   | DateTimeField             | 自动更新 | 更新时间                   |

**关系**：

- 一对多：居住地址 → 家庭

- 多对一：通知阅读状态 → 通知

## 4. 数据模型优化建议

1. **已实现的优化**：

   - ✅ 模型命名优化：`House01` → `Apartment`（楼房），`House02` → `SingleHouse`（平房），`NotificationReadStatus` → `NotificationRead`
   - ✅ 字段优化：`Resident` 模型中的身份证号已添加正则验证
   - ✅ 索引优化：已为 `Resident` 的 `id_card` 字段和 `Family` 的 `household_number` 字段添加索引
   - ✅ 数据完整性：已为 `HousingEstate` 模型添加了 `name` 和 `community` 的 `unique_together` 约束

2. **待优化建议**：

   - `Notification` 模型中的 `view_count` 可以考虑使用缓存优化
   - `ResidentialAddress` 模型中的楼房和平房地址关联可以考虑使用抽象基类或更好的继承关系
   - 对于外键字段，Django 会自动添加索引，但可以根据查询需求调整
   - 考虑添加更多的 `null=False` 约束，确保必要字段不为空

## 5. 总结

本数据模型设计覆盖了社区管理系统的主要功能需求，包括社区基础信息管理、房产信息管理、居民信息管理、通知管理和用户管理。模型之间的关系清晰，能够支持系统的各项业务功能。

在实际使用过程中，可以根据业务需求的变化和系统性能的要求，对模型进行进一步的优化和扩展。
